# 演示视频分镜脚本（总时长约 6 分 30 秒，MP4 / 1080p）

> 官方要求：演示视频 5–8 分钟，MP4、1080p；除功能演示外，**必须包含至少 2 分钟的「AI 协同过程复现展示」**（展示你如何输入 Prompt 让 AI 生成核心模块，或如何引导 AI 解决顽固 Bug）。
> 本脚本的 1:40–3:50 共 **2 分 10 秒**专用于该环节，且全部基于 `evidence/prompts/` 里真实发生过的修 Bug 链路，**不演戏、不事后补拍**。
> 录制人：参赛者本人。AI 不代录。建议 11-15 交付脚本、11-16 前录完并上传，给平台审核留缓冲。

## 素材清单（录制前先打开）

## 时间轴

### 00:00–00:40　痛点：我自己就是受影响用户（40 秒）
- **画面**：并排展示三份官方原文截图/文本——大赛通知页「2026年11月18日15:00」、参赛流程页 kdocs 直链、赛道详情页「缴费后个人中心查看，不再单独提供外部链接」；再切到国赛奖项同页 20% 与 25%。
- **口播要点**：「同一件事，官网、个人中心、赛道详情页写法不一样；高校转发通知的报名起始时间又和官网不同。学生要交作品，最怕的不是查不到，是查到好几个答案不知道信哪个——信错了，可能直接错过 11 月 18 日 15:00。」
- **注意**：不要念任何手机号/邮箱；屏幕上的个人信息需打码。

### 00:40–01:40　功能演示：裁决书而不是聊天（60 秒）
依次在界面输入（可直接用 `#q=` 链接切换，节省录制时间）：
1. `省赛作品提交截止是哪一天？` → 展示「有据可查」、裁决结论句「提交截止时间：2026年11月18日15:00」、`[1][2][3]` 原文片段、引用来源。
2. `国赛二等奖的获奖比例是多少？` → 展示裁决句并列 20% 与 25%，说明「同一官方页面自相矛盾，不擅自选定」。
3. `省赛答辩安排在哪一天？` → 展示红色「无依据 · 已拒答」+【证据缺口】说明去哪核对。
4. 停留在第一个问题的界面，展示**通知五要素卡片**，点击「下载截止日历提醒 (.ics)」并打开日历程序确认事件。
5. 快速切一个问题触发【渠道对照】或【条款级覆盖】（例：`官方通知和交接整理稿的说法不一致时，应该以哪个为准？`）。
- **口播要点**：「它不替我编答案，只把可核查的原文摆出来；没有依据时明确拒答，还会告诉我为什么查不到、该去哪核对。」

### 01:40–03:50　★ AI 协同过程复现展示（2 分 10 秒，官方硬要求）
> 这段必须由本人出镜/录屏操作，展示**你输入 Prompt → AI 定位 → 你指出问题 → AI 修正 → 回归测试**的完整闭环。以下三个真实案例任选两段，每段约 1 分钟。

**案例 A（建议必录）：P-005「空壳标题挤掉正确答案」**
- 画面 1：打开 `evidence/prompts/P-005.md`，展示当时的失败输出（问「省赛作品提交入口在哪里」，答案只有标题「二、作品提交方式」）。
- 画面 2：在 AI 会话里**由本人输入**类似指令：「检索排序里 official-01#4『二、作品提交方式』只有 8 个字却排第二，含直链的 official-03 没进 top8。请定位根因并加回归测试，不要只调阈值。」
- 画面 3：展示 AI 的回答要点（短文本 BM25 词频密度、小节标题单独成块）与改动：`app/chunker.py` 新增 `merge_headings`、chunk 数 69→55。
- 画面 4：运行 `python -m unittest discover -s tests -q`，展示新测试通过。
- 口播：「我没有让它猜，是让它拿排序数据解释为什么错；改完必须加测试锁死。」

**案例 B：P-008「我自己引入的误拒回归」**
- 画面：展示 `python -m app.server --selftest` 中 `POST /ask -> refused = True`（本应正常作答），说明这是修完 D1 语义拒答后的自引入回归。
- 本人输入 Prompt：「『选错组别会怎样』被拒答了，组别规则只在 demo 文档、断言索引没收录。请定位根因，不要直接把阈值调松。」
- 展示修复：加覆盖率保护（首位片段覆盖率 ≥0.30 不拒答）+ `test_d1_must_not_reject_covered_topic`，selftest 恢复 `refused=False`，三个应拒题仍正确拒答。
- 口播：「修一个 Bug 最容易带出另一个，所以我要求它先解释原因，再改，再回归。」

**案例 C（备选）：P-007「基准集发现我方落后」**
- 展示首轮对照表：结论正确率 45.8% vs 基线 75.0%、应拒尽拒 0%。
- 本人输入 Prompt：「不要粉饰，逐题抽查原始答案，定位三条真实缺陷并给可验证的修复方案。」
- 展示修复后 66.7% / 100% 与消融 Δ。
- 口播：「评测不是为了得到好看数字，是为了把短板变成可量化、可复验的改进。」

### 03:50–04:50　架构与评测（60 秒）
- 画面：`docs/technical.pdf` 第 5 章架构分层；`data/benchmark-v1.json`（24 题人工标注）；`evidence/eval-report.md`（主对照 + 消融矩阵）。
- 口播要点：「核心零第三方依赖；LLM 只在离线构建期抽断言、以及作为对照组的对手系统，运行时有硬门禁默认关闭。基准集的标准答案全部人工标注，LLM 只作被测对象、不作裁判——因为 TREC 的研究显示 LLM 裁判与人类完全一致率只有 56% 到 72%。消融显示关掉断言补充召回掉 20.8 个百分点，关掉语义拒答掉 12.5 个百分点。」
- 诚实一句：「但也如实写进文档：错误口径采信率仍高于生成基线，这部分我们不粉饰。」

### 04:50–05:40　10 分钟复现（50 秒）
- 画面：全新终端，依次执行 `python -m unittest discover -s tests -q`（35 个测试）、`python -m app.cli --eval`、`python -m app.server --port 8000`，浏览器打开界面。
- 口播：「全程不需要 API key、不需要联网、不需要装第三方包，断言资产和基准集都已固化入库。README 里有完整步骤。」

### 05:40–06:30　收尾：证据与边界（50 秒）
- 画面：`evidence/research/README.md` 的一手资料索引（池州学院校方回复、中国大学生在线、三校补充通知、期刊论文）；`git log --oneline`；`evidence/prompts/` 目录 9 条链。
- 口播：「痛点不是我编的：校方正式回复承认赛事信息分散，高校补充通知原文写着『以本补充通知为准』。九条 Prompt 链里有五条是真实出错后修 Bug 的记录。作品边界也写清楚了：词法检索、规则基线、经验阈值，换语料要重新标定。」

## 录制与交付注意事项

1. **分辨率 1920×1080、MP4、帧率 25/30fps**；导出前在系统里核对实际参数，不要凭第三方博客的参数表。
2. 录屏前关闭无关通知、隐藏浏览器书签栏；界面用深色主题、字号调大到可读（浏览器缩放到 125%）。
3. **AI 协同段必须能看到本人输入 Prompt 的动作**，不能只放最终代码；这是官方评分「过程可复现」的直接证据。
4. 所有含手机号、邮箱、QQ 群号的画面打码；仓库与视频里都不出现真实 API key。
5. 上传 **B 站或抖音**（官方表单明令「切勿提交百度网盘链接」），设为公开可访问；上传后用**匿名/未登录窗口**打开确认，并保存链接。
6. 若平台审核耗时，预留备用平台链接；视频链接填入表单第 7 项。
