# 界面模块规格 v1.0

> 适用范围：`app/web/index.html`（单文件、零第三方依赖，FastAPI 与标准库服务共用）
> 起草：2026-11-09　｜　对应提交：`feat(ui): 交互层扩展到 10 个模块`

本文件回答三个问题：**每个模块放在哪、点了会发生什么、长什么样**。
所有展示数据都来自本地资产（`data/*.json`、`data/docs/*.md`）或本次请求的真实返回，
界面不预先埋任何数字，接口缺字段时模块整体隐藏而不是显示占位假数据。

## 一、设计语言（全站唯一起源）

只允许使用下表 token，新增组件不得引入新的色值或圆角。

| 类别 | token | 值 | 用途 |
|---|---|---|---|
| 基底 | `--bg` | `#060a13` | 深空底，叠两层径向光晕 |
| 玻璃 | `--panel` / `--panel-2` | `rgba(15,22,37,.62)` / `rgba(11,17,30,.72)` | 侧栏与卡片，配 `backdrop-filter: blur(12~14px)` |
| 描边 | `--line` / `--line-bright` | `rgba(148,163,184,.14)` / `.26` | 默认态 / hover 态 |
| 文本 | `--fg` / `--fg-dim` / `--fg-faint` | `#e7edf5` / `#98a2b3` / `#6f7a8c` | 三级信息层次 |
| 强调 | `--accent` → `--accent-2` | `#38d9ff` → `#8b7bff` | 青紫渐变，仅用于"可交互/可核查" |
| 语义 | `--ok` / `--warn` / `--danger` | `#00e39c` / `#fbbf24` / `#ff5d73` | 有据 / 需核对 / 无依据 |
| 圆角 | `--radius` / `--radius-sm` | `12px` / `8px` | 卡片 / 控件 |
| 动效 | `--ease` | `cubic-bezier(.33,1,.68,1)` | 全部过渡统一缓动 |
| 时长 | `--t-fast` / `--t-med` / `--t-slow` | `.16s` / `.3s` / `.62s` | 反馈 / 展开 / 数据条生长 |

**视觉母题**：胶囊玻璃 + 1px 霓虹描边 + 渐变光扫。
**克制原则**：渐变只出现在"强调可交互"和"数据条"上；正文永远是纯色文本，避免霓虹底影响长文阅读。

### 补充模块

- **检索流水线**：提问后卡片内依次点亮"分词 → BM25 → 断言召回 → 拒答判定"四步，每步 350ms 左右。
  它只反映真实经过的函数，不伪造"思考过程"；请求失败时会话结束并显示错误卡。
- **追问建议**：回答下方按问题类型给 2~3 条追问（截止类给"入口/后果/文档要求"），点击即发。
- **Toast**：右下角 2.6s 自动消失，四色左边框（信息/成功/警示/失败），用于所有"看不见结果"的操作。

## 四、交互反馈规范

| 状态 | 表现 | 实现 |
|---|---|---|
| hover | 上浮 1~2px + 描边提亮 + 背景 +4% 亮度 | `transform: translateY(-1px)` + `--t-fast` |
| active | 回落并轻微缩放 `.985~.99` | `transform: translateY(0) scale(.99)` |
| focus | 青环 `0 0 0 3px rgba(56,217,255,.20)` + 1px 实边 | 全局 `:focus-visible`，键盘可达 |
| loading | 按钮禁用 + `.dots` 动画 + 四步流水线 | `disabled` + CSS 伪元素 |
| success | 按钮短暂变绿并改文案（"已复制"），1.8s 复原 + Toast | 类名 `done` |
| 失败 | 红色 Toast 写明原因，不弹模态 | `toast(msg,'err')` |
| 数据呈现 | 数字 520ms 滚动；进度条 620ms 生长 | `countUp()` + 宽度过渡 |

**动效预算**：所有过渡只改 `transform / opacity / box-shadow / width`，不触发布局重排；
`prefers-reduced-motion` 下全部动画缩到 0.001ms，粒子画布直接不创建。

## 五、键盘与可访问性

| 快捷键 | 行为 |
|---|---|
| `Ctrl/⌘ + K` | 开关命令面板 |
| `/` | 聚焦输入框 |
| `Enter` / `Shift+Enter` | 发送 / 换行 |
| `↑` `↓` `Enter` | 命令面板内选择与执行 |
| `Esc` | 关闭任意浮层 |
| `?` | 快捷键帮助 |

- Tab 使用 `role="tablist"/"tab"/"tabpanel"` + `aria-selected`；证据强度环带 `aria-label`；
- 配色信号均有文字等价物（"有据可查"/"无依据 · 已拒答"），不单靠颜色；
- 正文渲染用文本节点拼接 `[n]` 芯片，不用 `innerHTML`，答案含任意字符都不会破坏 DOM。

## 七、设计依据（2026-11-09 检索）

界面模式不是凭感觉加的，对应下列公开的设计模式总结：

1. **内联引用芯片 + 悬停/点击预览** —— Perplexity、ChatGPT Search 的基线做法，被列为 2026 年最常见的 RAG 引用模式（[aydesign.ai](https://www.aydesign.ai/blog/ai-rag-citation-ux-design-patterns-2026)）。
2. **证据侧栏（Source Browser）**：引用负责"指"，侧栏负责"让人真读"，并要求点击引用能滚到对应片段——
   本项目的 `[n]` ↔ 右栏联动即此模式（[AI UX Playground](https://aiuxplayground.com/pattern/retrieval-context-preview)）。
3. **渐进披露**：inline chip → 片段预览 → 完整来源列表，反对一次性倾倒 20 条 URL（[thepromptbench](https://thepromptbench.com/ai-product-ux/citations-inline-and-sticky/)）。
4. **可信度指示与诚实降级**：来源弱或缺失要可见地降级，而不是隐藏犹豫；同源指出"证据强度"应为可解释指标而非黑箱分数。
5. **冲突显式化**：多来源不一致时"reveal that tension instead of hiding it"（[Databricks: Provenance at Scale](https://databricks.cloud/provenance-at-scale-building-citation-and-source-pipelines-f)）。
   这正是本项目把它做成独立"冲突矩阵"而非塞进正文的依据。
6. **失败原因分类**：只给"踩"学不到东西，要给"来源不支持/来源太弱/无来源"的失败分类（[引用 UX 指南](https://aiuxplayground.com/guides/how-to-design-ai-citations)）。

## 八、边界与未做

- **不显示"AI 思考过程"**：只展示实际发生的检索步骤与分数，避免表演式推理。
- **不做来源打分的"假精确"**：证据强度是 0~100 的粗粒度指示，明确标注"不评价答案正确性"。
- **不做对话历史持久化**：刷新即清空，反馈只记在当前会话内存，不上传、不落盘。
- **移动端不做双栏**：<1080px 右栏转抽屉，避免正文被压到不可读。

## 九、接口失败态与版本错配（v1.1 新增）

这一节来自一次真实故障，不是预设场景。

### 现象

页面三个位置同时异常：右栏「脉络」「评测」显示"面板数据接口不可用"、左栏「渠道效力层级」整块空白、
「可核查资产」三格显示 `—`。同一时刻「证据」Tab、来源列表、问答都正常。

### 根因

不是权限、不是跨域、不是数据缺失，而是**页面是新的、后端进程是旧的**：

- `index.html` 由服务端每次请求从磁盘读，所以永远是最新版本；
- Python 进程在启动时把模块与索引加载进内存，之后改代码不会热更新；
- 本机当时并存 6 个历史实例（8000–8010，最早 20:09 启动），全部没有 `/api/overview`；
- 前端把 `overview` 的失败 `.catch(() => null)` 吞掉，于是"没有数据"和"接口不存在"长得一模一样。

旧进程内存里还是旧文档，所以顶栏显示的数字也和磁盘对不上——这恰好是判断"是不是旧进程"的最快线索。

### 处理原则

**失败提示必须能让人采取行动。** 只写"不可用"等于把排查成本全丢给用户。

| 失败类型 | 判定 | 文案 | 出口 |
|---|---|---|---|
| 版本错配 | `HTTP 404` | 后端没有 `/api/overview`：当前连接的是旧版服务进程。重启后端即可恢复——在项目目录按 Ctrl+C 停掉，再运行 `python -m app.server --port 8000`。 | 「重新请求」按钮；顶栏琥珀「数据不同步」 |
| 连不上 | fetch 抛错 | 连不上后端服务。请确认 `python -m app.server --port 8000` 正在运行。 | 「重新请求」 |
| 其他异常 | 非 404 的 4xx/5xx | 接口返回异常：HTTP 5xx | 「重新请求」；非 404 失败会**自动重试一次**（1.2s 后），避免瞬时抖动把面板打空 |

### 计数只认一个口径

原先顶栏 `文档/片段` 取 `/health`（进程内索引）、`断言` 取 `/api/overview`（现算自磁盘），
两个来源不同步时会出现"文档是旧的、断言是新的"这种半新半旧的数字。

现改为：**优先 `/api/overview.knowledge`（现算），退回 `/health`**；
两者不一致时点亮「数据不同步」胶囊，并在 tooltip 里写明两侧的具体数字。

### 无头环境不做装饰动画

`countUp` 依赖 `requestAnimationFrame`，在无头浏览器/后台标签页会被节流甚至挂起，
截图会停在动画中途（曾出现"文档 8 / 片段 53 / 断言 116"，而真实值是 10 / 64 / 141）。
现检测 `navigator.webdriver` 与 `HeadlessChrome` UA，命中则直接写终值。

这不是为了截图好看，而是避免**审计与存证材料本身说谎**——评委看到的数字必须等于真实数据。

### 复验方法

```bash
# 1) 正常态：三个数字应与磁盘一致
curl -s http://127.0.0.1:8000/health            # docs 10 / chunks 64
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/api/overview   # 200

# 2) 失败态：启动一个"旧版后端"，确认提示与出口都在
python tools/mock_stale_server.py --port 8040
# 访问 http://127.0.0.1:8040/#tab=timeline  应看到琥珀胶囊 + 原因 + 重启命令 + 重新请求
```
