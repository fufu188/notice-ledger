（1）项目详情及使用方式

项目是什么：一个面向大学生（尤其参赛学生）的「通知口径可信裁决」系统。它不生成流畅的聊天答案，而是把校务/赛事通知拆成可逐字核查的原子断言，回答时给出结论句 + 原文片段 + 引用 + 口径差异 + 渠道对照 + 五要素卡片，并在知识库没有依据时明确拒答、说明缺口在哪、该去哪核对。

解决什么问题：同一赛事通知分散在官网、高校转发、个人中心、提交表单与群内声明；写法不一致、会出补充通知、关键信息藏在会过期的附件里。学生要判断「到底哪天截止」「该信哪个链接」「补充通知改了哪些条款」，采信错误口径可能直接失去参赛资格。

怎么使用（3 步，全程离线）：

  1. 准备 Python 3.13；克隆仓库后执行 python -m unittest discover -s tests -q（35 个测试通过）。
  2. 运行 python -m app.server --port 8000，浏览器打开 http://127.0.0.1:8000/；或命令行 python -m app.cli "省赛作品提交截止是哪一天？"。
  3. 在界面输入问题，查看裁决书；点击「下载截止日历提醒 (.ics)」把截止节点导入日历；用 #q=<问题> 分享问题链接。

不需要 API key、不需要联网、不需要安装第三方包。FastAPI 版为可选薄封装，装好 requirements.txt 后接口语义一致。

（2）项目的亮点

  1. 反其道而行：不比「谁答得更像人」，比「谁的判断更经得起核查」。默认运行时不调用大模型，答案由规则层产生，天然无幻觉、可复现。
  2. 条款级覆盖：真实高校补充通知使用「申报方式和时间安排以本补充通知为准」「初赛复赛时间保持不变…其余按原通知执行」。系统按要求输出「哪些条款被覆盖、哪些明确沿用」，而不是把整份旧通知判为作废。
  3. 渠道效力层级：区分赛事表单 / 个人中心 / 官网 / 高校转发 / 群内声明 / 二手整理稿，同一事项的多种写法并列展示并给出行动影响，不擅自合并。
  4. 拒答会解释：不只说「不知道」，还说明「官方声明后续通知在群内发布，公开网页未收录，请核对教务处/牵头部门」，且不编造群内容或联系人。
  5. 证据来自外部一手资料：校方正式回复、学生来信、官方校园媒体、同行评审期刊、多校补充通知共同支撑痛点定义，而非自述。
  6. 可量化、可复跑：24 题人工基准集 + 10 组消融 + 固定基线对照，每个设计都能测出贡献（断言补充召回 −20.8pp、语义拒答 −12.5pp）。
  7. 可带走的工件：五要素卡片、RFC 5545 .ics 提醒、可分享问题链接，而非一次性聊天气泡。

（4）项目中涉及的关键技术

  • 中文 bi-gram + BM25：零第三方依赖的词法检索基线，配权威度与时效先验；可关闭的同义扩展解决「入口 vs 提交链接」词表不匹配。
  • 小节标题合并切分：避免 8 字空壳标题块因短文本词频密度高而挤掉含答案解析。
  • 日期归一化与口径差异检测：把多种日期写法归一键，小句级强时间词过滤，措辞为「口径差异」而非「事实矛盾」。
  • 语义级拒答：断言覆盖 + BM25 分数 + 问题词项覆盖 + 金额单位检查的组合规则，配套证据缺口说明。
  • 断言级补充召回：141 条已校验断言作为第二召回路径，解决数字/比例/页数类查询漏召回；补充片段用 [补充N] 标记，正文编号与 citation 严格一致。
  • 条款级覆盖模型：supersedes / scope / channel / as_of 字段，只采用通知原文的显式效力措辞。
  • 可证伪评测：人工标注基准集、确定性规则判卷、FS/PS/NS 加权归因、固定基线产物、10 组消融开关。
  • 双服务架构：标准库 http.server 与 FastAPI 薄封装提供同一组接口；Web 界面单文件、无 CDN、无框架。
  • 结构化工件：五要素规则抽取（缺失如实留白）、RFC 5545 .ics 本地生成（含提前 2 天 VALARM）。
