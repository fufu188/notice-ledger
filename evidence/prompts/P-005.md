# P-005｜带真实失败输出定位根因：空壳标题、词表不匹配、答案被冲突吞掉

- 日期：2026-11-09 19:30 — 20:30
- 工具 / 模型：WorkBuddy 会话（当前模型）
- 触发：P-004 导入真实官方语料后**自行跑测试发现的失败**，不是预设练习

## 一、失败现场（原样保留，不美化）

导入 5 条官方语料后，问「省赛作品提交入口在哪里」，系统返回：

```
回答：
据资料记载（以下为检索到的原文片段，非自动改写结论）：
[1] 本次省赛作品提交入口需参赛者完成缴费后，登录赛事个人中心所报赛项查看，不再单独提供外部链接。
[2] 二、作品提交方式
```

两个问题一眼可见：

1. 片段 `[2]` **只有一个标题**，没有任何正文 —— 用户拿不到半步可执行的操作。
2. 含 **kdocs 直链**的 `official-03` 根本没被召回。

排序实测（修复前）：

```
 12.353 official-02#6  本次省赛作品提交入口需参赛者完成缴费后…
  5.312 official-01#4  二、作品提交方式          ← 8 个字的空壳
  5.222 official-01#2  一、作品提交截止时间        ← 8 个字的空壳
  4.891 official-01#1  第九届传智杯…现已正式开放…
  4.730 official-01#10 请各位参赛选手尽快登录官网…
  4.662 official-01#6  三、特别提醒               ← 8 个字的空壳
```

`official-03`（含直链）**不在 top8**。

## 二、根因（分三条，都不是"模型不够强"这种借口）

**根因 1｜空壳标题在 BM25 里天然占优。** 中文语料里 `二、作品提交方式` 与正文之间有空行，`chunk_docs` 按空行切分 → 标题单独成块。该块只有 8 个字，BM25 的长度归一化会把短文本的词频密度放大，于是"标题块"以 5.312 分压过真正含答案的段落。三条空壳块合计占了 top6 里的三席。

**根因 2｜词表不匹配。** 用户问「**入口**」，官方原文写「提交**链接**」。bi-gram 一个都不重合，纯 BM25 必然漏召。

**根因 3｜有冲突就把答案整段吞掉。** `_offline_answer` 里 `if conflicts:` 的分支直接 `body = "\n".join(conflicts)` —— 用户问"截止是哪一天"，拿到的是一串并列日期，一句正面回答都没有。

## 三、修法（每条都对应一个回归测试）

| # | 改动 | 文件 | 锁死它的测试 |
|---|---|---|---|
| 1 | 新增 `is_heading` / `merge_headings`：短于 40 字且不以句末标点收尾的段落视为标题，粘到下一段正文上；合并后再按 320 字二次切分 | `app/chunker.py` | `test_heading_is_merged_into_body`、`test_heading_alone_does_not_become_dead_chunk` |
| 2 | 加 7 组领域同义词典（入口↔链接/地址/方式、截止↔期限/逾期、评分↔权重…），扩展词权重 0.45，**且可 `expand=False` 关闭**（为消融实验留口） | `app/retriever.py` | `test_synonym_expansion_bridges_entry_vs_link`、`test_expansion_can_be_disabled` |
| 3 | `_offline_answer` 改为「永远先给原文片段，冲突只作附注」 | `app/answer.py` | 已有的 `test_answer_does_not_repeat_same_source` 保持通过 |
| 4 | `_norm_date` 把「2026-11-18 / 2026年11月18日 / 2026/11/18」归一后再比对，同一天的多种写法不再误报为口径差异 | `app/answer.py` | 由 `test_conflict_*` 系列间接覆盖 |

## 四、修复后实测

**切分**：chunk 数 69 → 55（去掉 14 个零信息块）。

**排序**（问「省赛作品提交截止是哪一天」）：

```
 11.812 official-01#1  一、作品提交截止时间 / 提交截止时间：2026年11月18日15:00。   ← 正确答案排第一
```

**入口类问题**：`official-01#2`「二、作品提交方式 / 登录传智杯大赛官网，进入【个人中心】…点击【参赛流程】」进入 top4；含直链的 `official-03` 也进到 top2-3 区间（仍非第一，见下）。

**评测集**（8 题，全部指向官方真实语料）：

```
recall@3 = 6/8 = 75% | recall@5 = 8/8 = 100%
```

对比修复前只有 4 道 demo 题、recall@3 100% 的"漂亮数字"——**真实语料上的 75% 才是可信的基线**，README 已按此更新。

## 五、诚实留下的短板（不假装已解决）

- 「入口」类问题里，`official-03` 的直链仍排不到第一：BM25 对 URL 这种长 token 天然不友好，且查询词不含"链接"。下一步是混合检索（向量 + 词法）或对 URL 单独建字段，属 P-006。
- `detect_conflicts` 仍是规则基线，只在"强时间词 + 日期"这一窄面上工作；跨文档的语义级矛盾（例如措辞相反但日期相同）识别不了。README 里如实标为规则基线，不吹成"矛盾推理"。
