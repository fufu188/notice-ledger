## 意图（我要 AI 做什么）

P-001 产出的 v0.1 跑通了，但冒烟输出暴露质量问题：口径差异列表把「国赛报名 2026-12-10 至 2026-12-21」也算成截止口径，同一文档被重复列出，CLI 又把同一份清单打印了两遍。这会让「可信问答」这个卖点自己失信，必须在提交前修掉并加回归测试锁住。

## Prompt 原文 / 触发修复的证据

**真实性声明**：本次问题由 AI 自测输出暴露，用户本轮未单独下达修 Bug 指令；此处不虚构用户指令。触发修复的原始观察（CLI 输出摘录）：

```
- 2026-12-10｜国赛提交与省赛评审意见时间口径（DEMO 整理稿）｜...
- 2026-12-21｜国赛提交与省赛评审意见时间口径（DEMO 整理稿）｜...
- 2026-11-18｜省赛报名截止口径（DEMO 整理稿）｜...   ← 与前面重复来源
...
口径差异（需核对原始通知）：                          ← CLI 第二遍打印
```

诊断结论：`detect_conflicts` 用整个 chunk 文本匹配宽泛的 `TIME_WORDS`（含「报名」「开始」「前」），导致报名窗口所在句被整体纳入；且未对 `(日期, doc_id)` 去重。

## AI 的修改建议 / 生成内容

1. `app/answer.py`：新增 `CLAUSE_SPLIT`（按 `。；;，,\n` 切小句），`STRONG_TIME_WORDS` 收窄为 `截止 / 发布 / 公布 / 评审意见 / 答辩`；只有含强时间词的小句才贡献日期。
2. `detect_conflicts` 改为按 `(date, doc_id)` 去重，措辞仍为「口径差异」而非断定矛盾。
3. 新增 `_dedupe_by_doc`，`compose` 在过滤低分后按文档保留最高分片段，引用列表与 LLM context 同步去重。
4. `app/cli.py`：冲突明细不再二次打印，改为输出条数摘要。
5. `tests/test_core.py`：新增 2 个回归测试——报名窗口日期不得出现在口径差异中、同一来源不得在回答里重复。

## 如何引导 AI 修 Bug（官方要求环节）

- **第 1 轮 · 拿证据再下结论**：跑 `python -m app.cli "作品提交截止是哪一天？"`，把原始输出贴出来，要求先定位到具体函数与判定条件，不许直接改输出文案了事。
- **第 2 轮 · 要求修根因 + 加回归锁**：明确要求「按小句切分 + 收窄强时间词 + 去重」，并补 2 个单测把 bug 钉死；拒绝「只把 12-10/12-21 从列表里过滤掉」这类硬编码式修法。
- **第 3 轮 · 复验**：重跑 `python -m unittest discover -s tests -v` 与 CLI，确认 `2026-12-10`、`2026-12-21` 消失，`2026-12-27` 与 `2027年1月底` 保留，来源列表不再重复。
